# Feature status and boundaries

This release is a working modular application. The list below distinguishes implementation from production verification.

| Area | Implemented | Boundaries / remaining work |
|---|---|---|
| Organizations | Registration, settings, branch hours, time zones, grace policy, assigned branch access, consolidated reports | No cross-tenant platform console. Super Admin is deliberately tenant-scoped. |
| Authentication | Argon2, 10-minute bearer access tokens in memory, HttpOnly rotated refresh cookie, CSRF checks, replay revocation, logout, sessions, invites, activation, reset tokens, DB-backed rate limit | No MFA, SSO, captcha, email verification on local registration, or enterprise identity provider. Native concurrency of refresh rotation needs validation. |
| Authorization | Seven fixed roles, normalized role/permission tables, backend enforcement, staff branch assignments, private-field filtering | Arbitrary custom roles/permission editor is not implemented. A migration is needed for policy changes. |
| CRM | Create/view/edit/deactivate/archive, generated ID, photo validation/re-encoding, phone uniqueness, search, sorting/filtering/pagination, CSV import validation and authorized CSV export | CSV import is all-or-nothing, 1,000 rows/2 MB. Export capped at 10,000. Photo replacement leaves old files for administrative cleanup. |
| Memberships | Day-duration plans, exact prices/discounts/tax, invoice creation, paid activation, renewals, changes of plan at renewal, freezes, extensions, cancellations, grace periods, events | No calendar-month billing, automatic recurring charges, or immediate prorated upgrade/downgrade. Frozen access resumes by date. Cancellation does not automatically refund an invoice. |
| Attendance | Manual and server-token QR check-in, checkout, duplicate protection, branch/date eligibility, correction audit, history/date filters | No webcam QR decoder, biometric device, turnstile driver, or offline check-in. Trainer attendance is visible through assigned clients rather than a standalone payroll report. |
| Training | Trainer profiles/availability, client assignments, finite-session packages, bookings/rescheduling/cancellation/attendance, exercise library, workout templates/assignments/logs, private progress | No group classes, waitlists or recurring bookings. Package issuance is an authorized administrative entitlement; a separate manual invoice can charge for it. Cancellation releases a reserved session; completed/no-show sessions consume it. |
| Billing | Sequential organization invoice IDs, line totals/discounts/taxes, fixed manual payment methods, partial payments, receipts, refunds, cancellation history, expenses, dues and cash metrics | No payment gateway or webhook listener, SMS, GST filing, e-invoicing, accounting ledger, accrual revenue recognition or tax compliance certification. 'Other' supports a reference, not a configurable payment-method catalog. |
| Inventory | Suppliers, catalog, positive/negative stock movements, negative-stock guard, equipment assignment, maintenance history, linked service expense, low-stock alerts | No purchase orders, serial-level inventory, inventory valuation or depreciation. |
| Notifications | In-app receipts, expiry/renewal reminders, session reminders, low-stock/service alerts, deduplication and retrying scheduler; optional SMTP for activation/reset | Scheduled reminders are in-app. SMTP email invitation/reset sends are synchronous; delivery retry queue, SMS provider and webhook delivery receipts remain future work. |
| Analytics | Live DB counts, local-day attendance, period daily cash/refunds, outstanding balance, invoiced total, expenses, expiry list, retention/churn snapshot, branch comparison, trainer workload, CSV export | Reports currently aggregate bounded one-year periods in the API, with some all-time due calculations in memory. No enterprise load certification, precomputed warehouse or accrual analytics. Optimize further for very large tenants. |
| Frontend | Responsive role-aware navigation, operational forms, tables, dialogs, loading/errors/empty states, TanStack Query, member portal | Some creation forms intentionally expose a single invoice line; API accepts up to 100. Member detail/portal histories show latest records (25 / 100). Full visual and accessibility browser audits remain outstanding. |
| Delivery | Locked Python dependencies and npm lockfile, Windows launcher, migrations, optional demo, Dockerfiles, Compose, CI, backup/runbooks | Windows launcher, production images, HTTPS rollout, restore drill and native PostgreSQL concurrency have not been executed in this environment. |

All main screens call the real API. There is no fake frontend dashboard dataset, payment-success redirect logic or automatic production demo seed. The application must be independently reviewed and pass the remaining release gates before a public production rollout.
